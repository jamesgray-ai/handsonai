# Test's simulated leaders

Scripts for `test-workspace/evals/evals.json`, in the shared format (`framework-evals/students/README.md`): who you are, what you know, how you answer, when to stop. Each is the owner of the workflow in the eval's fixture; the fixture's files hold everything about the work, so the scripts hold only the leader's choices, their real example, and what only the leader can see.

`default.md` is the usual owner of Client Follow-Up. The simulation runs every hand-over for you and shows its answer on your screen, so you paste back (or, on Claude Code, say "next" after) what your screen shows: in a new chat on Claude on the web and desktop, ChatGPT and Microsoft 365, and in a new session in the workspace on Claude Code and Codex (`framework-evals/leader.py`, `simulates_leader_runs`), since a first round's practice set holds an input Test writes itself that no scripted block could match. The scripts still carry the blocks your runs end with ("Your runs"), written as a built workflow would write them: they are what a session marked `"leader_runs": "scripted"` pastes, the sessions whose script plants a run's block (a contaminated, injected or unsafe run) or whose fixture already holds what the run saved. The other scripts start from `default.md`'s facts and change one behaviour each. No script uses a framework or evaluation term.
