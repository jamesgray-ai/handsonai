> **Part of:** [AI Workflow Framework](../)

## What It's For

Build turns your approved Design Plan into a working workflow on your platform. Your platform's own tools make each part: Claude's skill creator, ChatGPT's, Codex's, Copilot's, or the platform's agent builder. Build writes each one a brief from your plan, checks what it made against the plan before anything is saved, and keeps a record.

## How the Skill Works

Build works in three parts:

1. **Your setup** — you connect each tool the workflow uses (Build reads something back to prove it's the right one). The workflow gets its own Project or folder only when it reads files when it runs; otherwise it runs in any new chat. With your OK, Build makes one quick real check of each kind of change, somewhere only you can see. When you've said the work already runs somewhere, Build asks about the older version, so the two never run side by side.
2. **Building and checking** — for each part, Build hands your platform's skill creator or agent builder a brief, in the same chat where the platform allows it. The creator drafts it, asks you what it needs, and tests it only as practice runs, so nothing is sent or changed. Build then checks the result against your plan, including the lines every practice run needs, word for word, and has the creator fix any gap before anything is saved.
3. **Save it and run it once** — you save the parts the platform's own way (a save card on Claude and ChatGPT; files on Claude Code and Codex), Build keeps a copy and writes your build record, and you run the finished workflow once in a fresh chat on one made-up example. If it stops to ask you something, that's the check: you never answer it as its user. Then Build gives you the phrase to start Test, ready to copy.

## What You Get

- **Your workflow:** its skills and agents, installed where it runs, each with a practice-run mode: start a run with "practice run" and it shows each change instead of making it. Practice runs are built never to send or change anything; if your platform asks you to approve a send or a change during one, choose Deny (or your platform's refuse button).
- **Your build record:** `build-record.md` in `framework/<workflow>/` in your working folder, saying what was built and what it can access.

## How to Start

Say **"run the build skill"** with where your files are, for example "run the build skill. My files are in Google Drive, in ai-workspace/framework/weekly-status-report." On Claude Code you can also type `/handsonai:build`.

## Worth Knowing

- **Your platform builds, Build checks.** Each brief comes from your requirement lines and the rules that must always hold, so every part can be checked against what it must do, whichever tool made it.
- **Where a builder has its own screen** (ChatGPT's Workspace Agents, Microsoft 365's Agent Builder), Build writes a short build prompt; you build the agent there and paste its instructions back into Build's chat, so Build can check they kept the lines every practice run needs.

**Next:** [Test](../test/) runs your workflow on practice inputs and one new input it hasn't seen.
