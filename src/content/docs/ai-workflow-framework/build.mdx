> **Part of:** [AI Workflow Framework](../)

## What It's For

Build turns your approved Design Plan into a working workflow on your platform. It works through the plan's tasks in order, checks each one against what it must do, and installs the workflow where it will run.

## How the Skill Works

Build works in three parts. You do almost all of your part in the first one:

1. **Your setup** — Build sets up the workflow's own place, has you connect each tool in your account and reads something back to prove it works, places the context files the workflow reads, and makes one quick real check of each kind of change somewhere only you can see.
2. **Building and checking** — Build tries the main skill on a plain AI first, then builds each task in your plan and checks it, showing every change instead of making it.
3. **Save it and test** — Build saves or installs the workflow where it runs, keeps a copy, writes your build record, and gives you the phrase to start Test.

## What You Get

- **Your workflow:** its skills and agents, installed where it runs, each with a practice-run mode. When you start a run with "practice run", nothing is sent or changed.
- **Your build record:** `build-record.md` in the workflow's folder, saying what was built and what it can access.

## How to Start

Say **"run the build skill"** with where your files are, for example "run the build skill. My files are in Google Drive, in Framework/weekly-status-report." On Claude Code you can also type `/handsonai:build`.

## Worth Knowing

- **It only tells the AI what it doesn't already do.** Build first runs the main task on a plain AI, with no instructions, and writes instructions only for what that run missed, plus the rules that must always hold. Shorter instructions are easier to check and easier to change.
- **On Microsoft 365 Copilot, agents are built in Agent Builder.** Skills are made in Copilot Cowork, where you run Build. For an agent, Build writes a short prompt; you open Copilot › Chat › Agents › New agent and paste it into the Agent Builder chat, add the context files Build names under Knowledge, check that only what the workflow uses is switched on under Work content, choose Create, and paste the agent's instructions back into Build's chat. The ordinary Copilot Chat can describe an agent but can't create one.
