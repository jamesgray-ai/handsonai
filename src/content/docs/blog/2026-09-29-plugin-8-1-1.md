A small follow-up to this morning's 8.1.0, from running the whole framework end to end as a student would. [Deconstruct](/ai-workflow-framework/deconstruct/) now saves each test scenario's input as a file under `outputs/<workflow>/inputs/` and puts the path in your requirements, so when [Test](/ai-workflow-framework/test/) hands you an input to run, it pastes the file for you. If you only described a real input, it asks you for it. Claude Code, Codex, and Gemini CLI entries in the platform registry gained the two facts Test reads to tell you exactly how to start a workflow in a new chat.

<!-- more -->

Also in 8.1.1: Test grades every line of the check list on every input, says "I can see the run above, so I'll grade it here" before grading, writes the round's file after you confirm the passing rule, and skips the connector check in one line when your workflow connects to nothing. Design and Build no longer announce phases that don't apply, the design spec has a one-line form for workflows with no integrations, and Build's install hand-off tells Claude Code users there's nothing to install and Cowork users to install the package. The [worked example](/ai-workflow-framework/examples/worked-example/) shows the saved inputs and the updated round.

Update from the [plugin marketplace](/use-the-playbook/build/), or download the [skill ZIPs](/ai-workflow-framework/skills/).
