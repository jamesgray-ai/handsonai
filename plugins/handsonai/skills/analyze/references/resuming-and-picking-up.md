# Resuming, later runs and the other lens

Read at a resume (the progress file is there, or on print-to-save a pasted report with a **Report status** block), when saving the progress file, on a later run (an existing report with no progress file), when the student runs the other lens, and for a 10.4 progress file or report.

## The progress file

`analyze-in-progress.md` in the framework folder, which makes "Progress is saved" true. Write it in plain words, since the student sees it written. Say nothing about it. It holds:
- **Run:** new / later (same lens) / other lens ([lens]).
- **Lens.**
- **Working folder:** dedicated or general (the web, Claude desktop and Cowork only; left out on Claude Code, Codex, the Work tab in a local folder and cloud sessions).
- **Goals and processes:** the goal map (`part-1-reading-and-the-lens.md`).
- **Sources,** per source name (`evidence-pass.md`).
- **The relationship and role answers** (no founding log line, no registry).
- **Dropped shortlist items,** as a count only (kept items are candidates, below).
- **Shortlist items not shown yet** (behind "show the rest"), by name, with their process, evidence clause and problem.
- **Running work:** name, home, regular use, "works well" or the improvement, and registry workflows to record as running.
- **Candidates:** name, description, process (new processes with their function), problem and its tag, trigger, deliverable, goal, frequency, volunteered size.
- **Flags:** do-more-of asked; follow-ups used (0–2); offers made (0–2).
- **Walking:** every process walked in this run, in order (the last is the one being walked); N-A17 never offers one of them again.
- **Stage,** the last step whose answer is saved: relationship / role / permission / shortlist / already runs / open question / follow-up on [piece] / do-more-of / offer / walk / new process function / list / list confirmed, nodes not written / fast path.

**Save points** (locally, and on drives that update in place):

| After | Holds |
|---|---|
| the relationship and role answers | Stage, the answers |
| the permission answer | Stage, and each source's answer (yes or declined); "read [date]" is filled at the next save |
| the shortlist answer (never before it, so only kept items are ever saved) | + kept items as candidates, Sources dates |
| the already-runs answers | + running work |
| each open-question playback and follow-up | + candidates |
| the do-more-of answer | + candidates, flags |
| the offer answer, and the walk | + flags, Walking |
| each new process's function | + the process |
| the list answer | everything |

**On a create-only drive** (one that can create and move files but not update them), save at four points only, never after each playback: after the already-runs answers (or the shortlist answer when nothing runs); after the walk; at the list; and at a pause or stop.

**Finish it** once the Workflow nodes are written (no registry: once `backlog.md` is written), or at the zero close: locally, delete it; on any drive, move it to `history/analyze-in-progress-YYYY-MM-DD-HHMM.md` in the framework folder, never delete it through the connection. Only the framework folder's own `analyze-in-progress.md` is ever resumed.

**On print-to-save,** keep no file. The report so far, with its **Report status** block (`report-format.md`), plays its part: give it, complete, with where it goes, after the open-question playback, after the walk, and at any stop, and say in one line that pasting it into a new chat with "run the analyze skill" picks up from it. At the close, give every file complete.

## Resume

The progress file exists (or a pasted report has a **Report status** block). It replaces the opening. Open with the one orientation line (SKILL.md, *Entry*), then say what was noted ("Last time I noted [candidates]."; with nothing noted yet, "Let's pick up where we left off."), then, when shortlist items not shown yet are saved, N-A19's "[n] more…" line for them, in its form (`evidence-pass.md`), so "show the rest" can bring them; then go to the saved stage, with the flags. The resume message asks one thing: the saved stage's question. N-A19's line in it is no second question: as on the shortlist, "show the rest" may be said in place of answering. When it is, the rest come as `evidence-pass.md` says, and after their answer the stage's question is not shown again in full: the open question, already shown in this chat, is repeated as its question sentence only (`the-walk.md`, *The open question*). The stages:
- **relationship** → the role question where it's needed, else N-A11 and the permission question (or N-A14's opening form);
- **role** → N-A11 and the permission question (or N-A14's opening form);
- **permission** → read again the sources the student said yes to, and draft the shortlist again, without asking N-A12 again;
- **shortlist** → the already-runs questions for kept items marked as already run, else the open question; kept items are already candidates;
- **already runs** → the name-and-home statement, then the open question;
- **open question**, **follow-up on [piece]** or **do-more-of** → the next follow-up or the do-more-of question the flags still allow, else *Enough to choose from* (`the-walk.md`);
- **offer** → the walk for the last process in **Walking**;
- **walk** → the second offer if one is left and there are still fewer than 3 (never for a process in **Walking**), else the list (or the zero close with none);
- **new process function** → the next workflow with no process, else the list;
- **list** → the list again;
- **list confirmed, nodes not written** → write the report and the nodes, then the close;
- **fast path** → the fast path's next step.

"Noted", for Deconstruct's unfinished-Analyze check, is any candidate. A pasted finished report (no **Report status** block) starts a later run.

## A later run

An existing report, no progress file, and no "start over". It merges into the same report, as the other lens does. Its sequence is the first run's:
1. the opening, in its later-run form (N-A10's first sentence only; the registry clause's later-run form, `part-1-reading-and-the-lens.md`);
2. the evidence pass;
3. the open question;
4. *Enough to choose from*, with fewer than 3 new candidates.

**What it offers again:**
- saved memory, past chats, typed requests, memory files and the project instructions file, always, as is any source declined on an earlier run;
- documents only when added or changed since their **Sources** date, with N-A12's later-run clause; where the connection gives no modified date, all documents again;
- a source with nothing new isn't named.

The evidence will meet the registered workflows' own documents and history, so expect the "Already in your registry" line (`evidence-pass.md`).

**On print-to-save,** the pasted report's processes with no card play the part of "processes with no Workflow node".

**"Start over"** on the same lens: first move the earlier report to `history/ai-opportunity-report-YYYY-MM-DD-HHMM.md` in the framework folder, then run as new and write a new report.

## The other lens

Offered only in the close (never for personal life). When the student runs it ("…with the individual lens"), run as a later run on that lens: N-A11's matching row (`part-1-reading-and-the-lens.md`), then the same sequence, merging. A piece matching a registered workflow: say "[Workflow] is already in your registry; I'll add what we learned to its card", update its card, and leave it out of the list's numbering and the close's [N]. Set **Lens** to "Individual + Organizational".

## Merging into the report

Add the cards under their processes, continuing the report's numbering (the list's 1 to N numbers are for the screen only); extend the Summary Table and the Candidate Summary; combine **Opportunities identified**; and update **Sources** per source. Every earlier card stays.

## Earlier versions (10.4)

**A 10.4 progress file** resumes like this, and is rewritten in the new format at the next save:

| It holds | Resumes as |
|---|---|
| "History: not checked yet" | The evidence pass (N-A12) |
| "History: checked; still to confirm: […]" | Those items shown again as the shortlist (N-A13), introduced in one line, in your own words, as items from last time still waiting for your answer; drafted guesses kept as "(my guess, …)", sizes dropped |
| "already handled" answers | The already-runs questions for those items |
| Noted pieces | Candidates; per-piece sizes go under *Current pain point* |
| "Run: picking up the rest" | A later run, merging |
| "Report written; list not confirmed yet" | Stage "list" |

**A 10.4 report's History row,** dated by the report's **Date**, maps to **Sources**:
- "Checked": saved memory and past chats read on that date; on Claude Code, also memory files and typed requests;
- "Declined": declined;
- "Nothing to read": not offered;
- documents: not offered.

**On merge,** drop the old report's Size column and **Not looked at yet** row. Old Size values move under *Current pain point*; "Already runs" moves to **Status**; **Goal** is filled from the registry for every old card.
