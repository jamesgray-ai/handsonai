# Variants

Each section is read only in its own case.

## Where it runs: the platform can't be identified, or the leader names another

Read at Part 1 when you can't tell which platform this is, or when the leader's reply names a product or an ecosystem to run it on.

When the platform can't be identified, instead:

**Ask:** "Where do you want to use this workflow? Tell me the AI tool you use day-to-day — for example, ChatGPT in your browser, Claude in your browser, Microsoft 365 Copilot, Claude Code in your terminal, or something else."
- *Why:* This decides where the final workflow lives and what format I'll build it in.

Map any answer to one product yourself. For a non-technical leader, the browser or no-code option: "Claude" means Claude on the web or desktop, "OpenAI" means ChatGPT, "Microsoft" means Microsoft 365 Copilot in Cowork. A bare "Cowork" names two products (Claude's and Copilot's): pick the likelier from what the leader has said (a work Microsoft account, OneDrive or Outlook points to Copilot Cowork), and give the confirm-back line below naming the other as the nearest other product. Choose Claude Code or Codex only on a clear sign the leader works in code. Never ask a leader to choose between technical forms. When the leader names an ecosystem rather than a product, say exactly: "Got it — I'll design this for **[product]** ([where it runs, in plain words]). If you actually meant [the nearest other product], or something else, say so and I'll switch." (For example: "Got it — I'll design this for **Claude** (on the web at claude.ai or on desktop). If you actually meant Claude Code in your terminal, or something else, say so and I'll switch.") Designing for another platform (a teammate's ChatGPT) is allowed through the correction.

## The review: `Path: none` with planned steps, `domains`, and regulated work planned as Autonomous

Read before writing the review of such a plan. These lines go before and after the level in the review's first item (SKILL.md, *Phase 4*).

For `Path: none` with planned steps, the recommendation comes before the level, so the level describes the plan you recommend, said exactly (B54): "This work [has one input and rules that settle each decision], so a fixed set of steps will be more reliable than working it out each time. I'll plan those steps; you can still change this." When that plan is still Guided, add one line (model wording) naming the step that makes its own decisions, so the level that follows is heard as that step's, never as the whole workflow working out its own steps (for example: "Gathering the figures is the part it works out each time: it chooses where to look until every number has a source."). When it is still Autonomous, say no such line: the level takes its planned-steps form, in place of the Autonomous line in `review.md`, said exactly: "How much it decides on its own: Autonomous, for [the step, in plain words]. You give it a goal there: it plans that part's own steps and keeps going until the goal is met; the rest follows the steps in this plan."

After the level, where they apply, said exactly: for `domains` with no order the leader insisted on, "None of this has to happen a set way, so I've planned it as the abilities the AI draws on rather than fixed steps." (D8′); for regulated work planned as Autonomous (D3′), "Your work falls under [regime], and it can still work out its own steps: what the rules require stays exactly as it is, and every decision a person must make stays with a person. The plan also adds a record of what it did on each run, so you can check it later." And one line when you wrote fixed steps inside an AI part.
