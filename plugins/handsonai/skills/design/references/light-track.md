# The light track

Read when the requirements say `track: light`, before drafting the plan, and when Build reports a track switch.

`track: light` in the requirements: the same four parts, file and format. Part 3 asks at most three questions. The review is one message: the main choices (where and how it runs, how much it decides on its own, what it reads and changes), the tasks in plain words, anything assumed or defaulted, the plan check line and any open items; with no consequential points it ends with "Do you approve the plan? Build won't start until you do." instead of "What would you change or clarify?", and a correction goes through `review.md`'s *Changes*; with points, the points and N-6 as on the full track. Sections stay short (Integration Options and Data Readiness are often one line). Risk inputs take one of the three places Test runs, never a fourth.

**The automatic switch.** When a light workflow shows a sign of risk (a change that can't be undone, a write to a shared or live system, running without the leader, regulation, confidential or outside content), judged on the writes the workflow needs (never on access the plan check removes) and by the floor in `plan-template.md` (a draft no one sees until a person sends it, or a new file only the leader sees, is no sign: its clause "sends, posts or changes something other people see" is for a send, a post or a change to something other people see, never for a draft or file only the leader sees), say N-L2 (model wording ending with its promise clause: "This [changes something that can't be undone / sends, posts or changes something other people see / runs without you / is regulated / reads confidential details or content from outside your team], so it needs a few more safety answers."), then the next action, and write `track: full` to the requirements (no `revision` raise). From then on the full track applies. If the plan needs one answer Deconstruct didn't capture, ask that one question (in Deconstruct's approved wording) and record it with N-15, raising `revision`; nothing else is asked as a block. When the switch comes from confidential or outside content and the Security section is still the light track's one-line form ("No sensitivity constraints — …", written before that content counted as a sign), the security limits are that missing answer, never settled by that line: draft them in one message, each in plain words under its category, each kept or dropped, and record what's kept in the Security section with the next `P` ID.

**A missing safety answer, on any file.** Deconstruct's interview is short, so a file can arrive without a safety answer the plan needs, whatever its `track:` says: a write with no Prohibited actions or Traceability line, confidential or outside content with the Security section still in its one-line form, a run without the leader with no Fallback or flag place. Treat it as the automatic switch treats it: ask the one missing question (in Deconstruct's approved wording), or draft the security limits in one message, each kept or dropped, and record what's kept with N-15, raising `revision`. No N-L2 is said for a file already marked `track: full`.
