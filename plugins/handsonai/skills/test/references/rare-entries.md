# Entries that are rarely needed

Read at entry when one applies: a direct edit is found or the installed workflow can't be read; this chat runs in a different account or place than the build record names; or the last round closed on the policy check. Section names in italics are SKILL.md's; the numbers are SKILL.md's entry checks.

## Entry check 2: a direct edit found, or an installed workflow you can't read

Where you can't read the skills, **Ask:** "Have you edited the workflow's instructions or its files directly since it was built?" Where you can read them but a runtime context copy can't be read: **Ask:** "Have you edited the files your workflow reads ([the files, in plain words]) directly since it was built?" For an agent Agent Builder made: **Ask:** "Apart from pasting the prompts I wrote, have you changed [Agent] in Agent Builder, or its Knowledge, since it was made?", skipped when the leader comes straight from Build (no round has opened since Build's last close, so `last_close_after_round` is the last round's number or no round exists, and that close made or fixed the agent). On a yes where the text can't be read, say "Paste [the instructions / the file] as [they are / it is] now, so I can match your requirements and plan to [them / it]. [How to copy it out on this platform.]" Then, for an edit found:
   - **Any other edit:** **Ask:** "I'll record that as a change so your requirements and plan match. OK, or should I put back the built version?" Keep (the recommended default): open the round's file if no round is in progress, record a change request (`source: direct edit`, its `id` `T[round].[n]`; the edited text saved as `history/direct-edit-[id]-YYYY-MM-DD-HHMM.md`, and `what` a one-line summary, in double quotes, naming that file: the text itself never goes in the frontmatter), and give Design's start phrase with the location (model wording). Put back: open the round's file the same way, record `direct_edit: undo`, and give Build's start phrase with the location. Either way, stop.
   - **An edit Design already declined** (its text matches the edited text saved in the file the `what` of a `direct edit` entry names, an entry the plan's `changes:` logs as declined): **Ask:** "That edit changes [the fixed step, in plain words], which your [rules require / policy requires], so it can't be kept. Shall I put back the built version?" A yes: the put-back above. A no: say "Then I'll leave it as it is. While that edit is installed, I can't [test / build / change] [workflow]. When you want the built version back, say '[this step's start phrase]. My files are in [location].'" and stop, opening no round and writing nothing.

## Entry check 3: a different account or place

**A different account or place.** Where you can see this chat runs in a different account or place than the build record names (another workspace, or a connection that reads a different account): **Ask:** "Is [workflow] installed in this [account / place]? Say yes, or I'll give you the steps." (N-T2) Then run a read check of each connection, as Build's setup does. A missing connection or permission: say "[Tool] isn't connected with the permission your workflow needs to [the action]. [Steps, including which permission to allow and which to leave off.] Say 'done' when it's connected." (N-T46) and wait for "done". Write nothing until it passes. The go-live message then lists every kind of change as a first-time item.
