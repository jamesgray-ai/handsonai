# Part 2: Scope and a name

Read when Part 2 starts, right after its signpost. Every quoted line is said exactly. In a personal-life registry, the personal-life wording replaces the trigger and deliverable questions and the law question is skipped.

## One trigger, one deliverable

A workflow has exactly one trigger (what kicks it off) and one deliverable (the thing it produces). Confirm both: they are prefilled from the backlog candidate or the describe-first answer, so play them back and ask one question ("Does that match?") rather than re-asking. Run the tests below yourself; don't turn them into questions. Test for more than one workflow:

- **Triggers:** several independent starting points ("when a lead comes in" and "end of each week") → separate workflows.
- **Deliverables:** someone receives a deliverable midway while the work goes on toward a different output → a workflow boundary.
- **Timeframes:** parts run on different schedules, or with long waits between them → likely separate workflows.
- **Size:** it would grow past about 15 steps → may be several workflows.
- **Ownership** (Organizational lens): no single accountable owner of the end-to-end outcome → may be several workflows.

If you find several, map each (working name, trigger, deliverable), present the breakdown, confirm the boundaries, and ask which to deconstruct first. Continue with the chosen one only.

## The name

Present 2–3 name options: a **2–4 word noun phrase** in **Title Case**, clear without context ("Lead Qualification", "Newsletter Distribution", "Student Onboarding"). Prefer `[Subject] [Action]` ("Invoice Generation", "Inbox Triage") over verb phrases or vague labels. Ask only which name they want; confirm the description in the next message, on its own.

Convert the confirmed name to kebab-case (lowercase, hyphens, no punctuation) and confirm it: "I'll use `lead-qualification` as the workflow ID — it names the folder and files for everything we produce." This ID names every file path; every downstream skill uses it verbatim.

**A rename keeps the node.** If the student renames a workflow that already has a Workflow node, the folder takes the new ID, the node keeps its file, and no new node is made: the progress file's `Workflow node:` line names the original node, and everything merges into it at the end.

## The law or regulation question

Asked as the last question of Part 2. Skipped for personal life (`Governing regime: None`). If the student already answered it in an earlier reply, record that answer and don't ask again.

**Ask:** "Is there a law or regulation that governs this work?"
- *Not sure?* Say not sure; I'll note it for you to check.

On a yes, in its own message, **Ask:** "Which one? A name or a description is fine." Then say: "Because this work is regulated, this will take a little longer: we'll note which steps and decisions the rules cover."

Record it for Security, Privacy & Safety as one line: `Governing regime: [name]`, `Governing regime: None`, or `Governing regime: Not sure — to check` (a "not sure", or a yes whose name stays unknown).

- **A yes** (even with the name unknown) switches on Part 4's detail table and its two regulation questions.
- **"Not sure"** switches on neither; Design asks the student to confirm before it lets the AI decide on its own.

Once the name and this answer exist, save the progress file (the rule in SKILL.md).
