# Storage: the working folder

Read only when there's no working folder yet (on the web or in Microsoft 365 Cowork), or on Claude desktop with no folder selected and no location given (SKILL.md, *Storage and saving*). Never on Claude Code, Codex, the Work tab in a local folder or in a cloud session. Never for a location the leader's start phrase gives ("My files are in …"): that folder exists, so it is never asked about or offered for creation here; when it can't be found or read, that is files this chat can't read (`location.md`, N-F13). Every quoted line is said exactly.

- **The storage question** (N-F1). On the web or in Microsoft 365 Cowork with no working folder yet, Deconstruct is the leader's first step: ask it as the first message, before the opening and before anything is saved (N-F16 first where it applies); the opening, with N-F3, follows the answer. On the web, filling [storage service] with the storage services connected in this chat whose connection can create files, by their own names ("Google Drive", or "Google Drive or Dropbox"); where you can't tell which is connected, "connected storage": **Ask**, in full (every sentence, in order; none dropped, merged or shortened): "Where should your working folder go? It holds your AI Registry, your workflows and your knowledge graph. Say 'go ahead' and I'll make a private folder called ai-workspace in your [storage service], or tell me the name of one you already have. To keep it somewhere else, such as Google Drive, OneDrive or Box, add it to this chat from the prompt box first. The connection reaches your whole drive, but I'll only read and save inside that folder, and never share or delete anything. Run each step of the framework in a new chat that isn't inside one of your [Claude / ChatGPT] Projects." Where [storage service] is only the AI's own library (no drive in this chat), its fourth sentence is "I'll only read and save inside that folder, and never share or delete anything." In Cowork: **Ask:** "Where's your working folder? It's the one folder that holds your AI Registry, your workflows and your knowledge graph. If you already have one in your OneDrive, tell me its name. If not, I'll make a folder called ai-workspace there, separate from Cowork's own folder. Cowork can see your whole OneDrive, but I'll only read and save inside your working folder, and never share or delete anything. Please run each step of the framework in a new Cowork chat. Say 'go ahead', or tell me your folder's name."
  - *Why:* Every step reads and saves these files, so a new chat needs to find them.

  Never assume the leader has a working folder, or that they don't. On "go ahead", make `ai-workspace` before the first file is saved. When they name a folder, use it: first look for it: where it isn't in the [storage service] (or the folder), ask N-F17, "I can't find [folder] in your [storage service]. Shall I create it there? Say 'go ahead', or tell me another folder's name.", and on "go ahead" make it there; ask for a link only when the folder clearly exists but can't be reached by name; and when it's a general folder (a drive's top level, or a folder named Documents, Desktop or Downloads, or the home folder), ask the big-folder follow-up (N-F15) before saving anything: **Ask:** "That folder holds a lot besides your AI work. I'd suggest a new, clean folder called ai-workspace instead, so the framework only ever touches your AI work. Say 'go ahead', or 'use it anyway'." On "go ahead", make `ai-workspace` and use it; on "use it anyway", use the folder they named. When you're unsure whether any other folder is one (its file names show a lot besides AI work), ask N-F15b instead: **Ask:** "Is this a folder you set up for your AI work?" On yes, use the folder; on no, ask the big-folder follow-up. A folder that holds only `registry/`, `framework/` and `knowledge/` is never asked about. The workflow's folder goes in the working folder's `framework/` folder, made when the first file is saved.

  - *Why:* Every step reads and saves these files, so a new chat needs to find them.
