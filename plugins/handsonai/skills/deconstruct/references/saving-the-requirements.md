## Registry write

On the Workflow node the progress file's second line names (`registry/workflows/[slug].md`; in a drive or on Claude desktop, the registry inside the working folder, written through the connection on the web and in Cowork), resolved and written as the indexing-registry skill's `registry-bundle.md` says. Only these fields; a field another step or the leader set is never overwritten, though a stub's provisional `trigger` may be replaced:
- `status: under-development`, from `backlog` only; any other status is kept, including on a re-run, a redo and running work brought in (which stays `in-production`);
- the refined `trigger`;
- the `description` the leader accepted, word for word, the same sentence as the requirements' Metadata;
- after a rename (`interview.md`, *A rename keeps the node and its ID*), the new name as `title` and as the body's first heading; the file name, and so the node's ID, never changes;
- the "Requirements" link under `# Artifacts`, relative to the registry's parent folder, never `../`, in one form on every platform: `- [Requirements](framework/[slug]/requirements.md)`. Deconstruct writes only this link; any other link on the node stays as written (an older `[slug]/…` link still resolves through `framework/`);
- after a redo, `big_change` removed (the registry-log line stays);
- `generated: { by: process:deconstruct, at: [now, a UTC instant, YYYY-MM-DDTHH:MM:SSZ] }`.

**A new node** (cold entry with a registry and no backlog node): `naming-workflows`' stub format with `status: under-development` and no process or owner field, its line in the `# Workflows` list of the Process the interview placed it under; a Process (and any new Function) from Analyze's no-process question is written as Analyze writes them.

Then the indexing-registry skill's maintenance pass, best effort: a failed refresh never fails Deconstruct. To fix it, say 'update my registry. My files are in [location].'" [location] is the working folder, as a start phrase names it: "Google Drive, in ai-workspace" or "OneDrive, in ai-workspace" in a drive, with the storage service's own name, its own name on Claude desktop. On Claude Code and Codex: "Your dashboard wasn't refreshed this time, because something in your registry needs fixing first. To fix it, say 'update my registry.'" Run its tools only as that skill gives them, on the registry inside the workspace; Deconstruct never deletes a file, so anything a refresh wrote in the wrong place stays, named to the leader in one line (model wording). With no registry, nothing is written, and nothing is said about it beyond the no-registry line. The dashboard's Claude page is mentioned only when the pass gives it a new link (that one line); a page that couldn't be updated on this platform is never mentioned, and neither is the dashboard file being up to date.
